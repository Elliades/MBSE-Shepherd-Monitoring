# Scenario library

Simulation scenarios written as text (`.scn`), compiled to the `*.scenario.json` read by
MBSE Shepherd > Simulation Scenarios and by "Validate in Cameo".

- `scenario-dsl.js`: the language (parse, print, compile, fromJson). The full grammar is in its header.
- `library/`: the public scenarios (Part 3, per architecture; `variants/` written by hand, status draft).
- `private/`: gitignored, the plugin's scenarios of the functional mission (answers of the graded Part 2).
- `index.html`: the viewer. Story, step × part matrix, live source editing, compiled JSON, JSON import.
- `out/`: the compiled JSON, regenerated by the build.

```bash
node scripts/scenarios-build.mjs
```

The build checks every file, compiles it, and checks both round trips: text → document → text, and JSON → DSL → JSON.
Then open `/scenarios/` on the dev server (or `index.html` straight from the disk).

## One scenario, one thing

```
scenario: A bear enters the tracking perimeter
id: arch1.bear-enters
kind: nominal                      # nominal | alternative | dysfunctional
version: 1.0
status: in use
goal: Predator defense takes over and the drone follows the bear.
given: arch1.mission-start         # preconditions: played first, waited for, not measured

phase Predator response
  step bear: pasture sends Predator Detected inside tracking perimeter
    note: The bear is seen.
    then soi.orch is Predator Defense Active
    then soi.pd is not Awaiting Control
    then message Predator Alert
```

- `given: a, b`: preconditions, each one resolved with its own givens, and each played once.
- `sequence: a, b, c`: an assembly. Every scenario in it is measured, in that order.
- `from: a`, then `after <step>:` / `before <step>:` / `instead of <step>:` / `remove <step>` / `cut after <step>`: a variant.
- `assume <part> is <state>`: a starting state, checked on the last step of the preconditions.
- `fault: …`: stated, not injected. The plugin cannot break a connector yet.

## Writing and playing scenarios (people and LLMs)

The skill `.claude/skills/mbse-scenarios/` (plain Markdown, any LLM can follow it) gives the method: unit scenarios,
assemblies, variants, then playing them in Cameo and judging the architecture. Its runner:

```bash
node scripts/scenarios-run.mjs <id | file.scn | dir> [--check] [--report out.json]
```
